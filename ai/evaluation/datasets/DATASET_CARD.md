# Evaluation datasets — SYNTHETIC

> **Every record is synthetic.** Generated by `ai/training/src/synthetic/` from hand-written template phrases (system design §58: "All demo data must be explicitly labelled as synthetic/demo data"). Not real citizen reports; Hindi/Marathi phrasing is unreviewed by native speakers.

| File | Rows | Used for |
|---|---|---|
| `intake_eval.v1.jsonl` | 216 | AI-1 intake classification/routing (§57: 100–300 labelled reports) |
| `fusion_eval_pairs.v1.jsonl` | 300 | AI-2 duplicate detection (gated candidate pairs) |
| `manifest.v1.json` | — | Seed, parameters, split design, **sha256 of every train/val/test file** (reproducibility check) |

## Construction
* 27 subcategories × 4 languages (English, Hindi, Marathi, romanised Hinglish) × 5 hand-written *template families* (core phrases). A class `other/unclassified` covers vague/off-topic reports.
* Rendering adds: place names (with Latin/Devanagari variants), optional prefixes/suffixes, **spelling noise** (cluster-safe for Devanagari), casing/punctuation noise, and **code-mixing** (native frame + English core, Latin place names inside Devanagari text, Indian-English + Hindi suffixes).
* **Held out by template family and by place pool.** Family index 4 (and place indices 4, 9, 14, 19) form the test pool; index 3 forms the validation pool; train never sees either. Frames, prefixes, suffixes and noise processes are shared across splits (they carry no label information). `--test-fold k` rotates the held-out family for 5-fold family-grouped CV.
* Pairs: duplicates (same event, different phrasing/language, GPS jitter), hard negatives (same subcategory 20–145 m apart, same category/different subcategory), far pairs (outside the candidate gate), and recurrences (>35 days apart).

## Record fields (intake)
`id, split, family_id, language, code_mixed, noisy, text, category, subcategory, department, gold_severity, location_tags, place_id, synthetic, generator_version`

## Known limitations (read before quoting any number)
1. Same generator for train and test: unseen *phrases*, not unseen *processes*.
2. `gold_severity` is derived from the taxonomy base severity plus a school/hospital bump — the same assumption the rules use. Severity agreement on this set is **circular** and only checks rule consistency.
3. Duplicate pairs encode our assumptions (small GPS jitter); distance dominates the score. Lexical text similarity is mono-lingual and uninformative here by design (duplicates use different wording).
4. One held-out family per class/language → wide confidence intervals (see Wilson intervals in reports, or run CV).
5. No real-world noise (speech-recognition errors, long rambling reports, photos, slang beyond the templates).
